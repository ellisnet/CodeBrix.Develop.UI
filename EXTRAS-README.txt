================================================================================
EXTRAS-README: CodeBrix.Develop.UI
Samples, tools and other content in this repository that is not part of a NuGet
package
================================================================================

There is NO samples/ folder and NO demo application in this repository. The
non-package content is the generation tooling, the two Roslyn integration
projects, the test project, and one leftover test asset. Each is described
below.


THE BINDING GENERATOR (src/Generation/)
=======================================
Four projects, none of them packable and none of them shipped to consumers.
They exist to produce the `*.Generated.cs` files that make up most of the
binding.

    src/Generation/CodeBrix.Develop.UI.GirModel/
        The object model of the GObject Introspection (GIR) format.

    src/Generation/CodeBrix.Develop.UI.GirLoader/
        The .gir XML parser/loader that fills that model.

    src/Generation/CodeBrix.Develop.UI.Generator/
        The C# code emitters (renderers plus the file publisher that stamps
        every output with `// <auto-generated/>` and a blanket
        `#pragma warning disable`).

    src/Generation/CodeBrix.Develop.UI.BindingTool/
        The command-line driver — the fork of the upstream GirTool. This is the
        only one you run directly.

    src/Generation/Shared/
        Non-project shared sources used by the four projects above.

How to run it:

    dotnet run --project src/Generation/CodeBrix.Develop.UI.BindingTool -- \
        generate <gir files...> --output src

    dotnet run --project src/Generation/CodeBrix.Develop.UI.BindingTool -- \
        clean src

The full regeneration command line, the option list, and where the .gir input
files come from are documented in MAINTAINER-README.txt under GENERATING THE
BINDINGS. `generate` acquires its inputs from the companion snapshot repository
https://github.com/ellisnet/CodeBrix.Develop.UI.GnomeIntrospection at a pinned
commit and caches them in ./.gir-cache/ (gitignored), so repeat runs work
offline.


THE ROSLYN INTEGRATION PROJECTS (src/Integrations/)
===================================================
These two ARE shipped — as analyzers inside the CodeBrix.Develop.UI package —
so they are not "extras" for a consumer. They are listed here because they are
separate projects in the solution with their own build rules.

    src/Integrations/CodeBrix.Develop.UI.GObject.Integration/
        Source generator for `[Subclass<T>]` GObject types, plus the analyzer
        rules GirCore1002, GirCore1004, GirCore1005, GirCore1006, GirCore1008.

    src/Integrations/CodeBrix.Develop.UI.Gtk.Integration/
        Source generator for `[Template<TLoader>]` / `[Connect]` GTK composite
        template widgets, plus the analyzer rules GirCore2001, GirCore2002,
        GirCore2003.

    src/Integrations/Shared/
        Shared TypeData helpers, the attribute-recognition helpers, the
        diagnostic help-link builder, and the netstandard2.0 compatibility
        shims (IsExternalInit, NullableAttributes).

Both target netstandard2.0 rather than net10.0 — see MAINTAINER-README.txt
under BUILDING for why, and why that must not be "fixed".

What they generate and how to consume them is documented for package users in
AGENT-README.txt under GOBJECT SUBCLASSING AND THE SHIPPED ROSLYN ATTRIBUTES
and COMPOSITE TEMPLATES.


THE TEST PROJECT (tests/CodeBrix.Develop.UI.Tests/)
===================================================
The only non-package project that is neither tooling nor shipped. It is also
the best worked-example collection in the repository — AGENT-README.txt points
consumers at individual files under WORKING EXAMPLES ON GITHUB.

    Cairo/       ports of the upstream Cairo suite (Context, ImageSurface,
                 Pattern, Matrix, FontFace, FontOptions, ScaledFont)
    Gio/         SimpleAction / GLib.Variant state
    GLib/        Variant, VariantType, SList, PtrArray, Dir, error and
                 exception mapping, unowned handles, and the main-loop
                 SynchronizationContext
    GObject/     Type, Value, ParamSpec, interfaces, SList extensions
    Gtk/         constructors, methods that can return null, generated
                 properties, signals, interface members
    GtkSource/   runtime smoke tests for the GtkSourceView binding
    ModuleInitialization.cs
                 the assembly-level module initializer: initializes the whole
                 native module tree once and makes native GLib criticals,
                 errors and warnings fatal; also disables test-assembly
                 parallelization, because GTK is single-threaded
    PackageSmoke.cs
                 native-free checks on the shipped assembly/namespace shape

Running it (including the MTP runner requirement, the coverage extension and
the native prerequisites) is documented in MAINTAINER-README.txt under TESTING.

    dotnet test CodeBrix.Develop.UI.slnx


OPTIONAL AND LEFTOVER TEST DATA
===============================
    tests/CodeBrix.Develop.UI.Tests/Gtk/test.bmp
        A small bitmap carried over from the upstream test suite (it backed the
        upstream GdkPixbuf texture tests) and recorded as such in
        THIRD-PARTY-NOTICES.txt. No test source in this repository references
        it today, and the test .csproj does not copy or embed it. Keep it if
        the texture tests are ever ported; it costs nothing.


GENERATED AND CACHED FOLDERS (not content, not committed)
=========================================================
    .gir-cache/     GIR snapshots downloaded by BindingTool, keyed by git ref
                    and split into linux/, macos/ and windows/ subfolders.
                    Safe to delete; the next generate run re-downloads it.
    TestResults/    output of `dotnet test --coverage`.
    bin/, obj/      and every `*.Generated.cs` file under src/.
All of the above are gitignored.
